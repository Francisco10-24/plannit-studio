--- p3 ---
Bloque 1: POST con http
http.post(Uri.parse(url), body: jsonEncode(datos), headers: {'Content-Type': 'application/json'})
El cuerpo se envía como texto JSON: por eso jsonEncode, 
el inverso de jsonDecode
Un POST exitoso contra JSONPlaceholder responde con 
código 201 (Created), no 200

--- p4 ---
Bloque 1: PUT con http
http.put(Uri.parse('$url/$id'), body: jsonEncode(datosActualizados), headers: {...})
PUT reemplaza el recurso completo identificado por su 
id en la URL
Un PUT exitoso contra JSONPlaceholder responde con 
código 200

--- p6 ---
Las grietas de http
¿Qué pasó cuando alguna de las dos solicitudes falló? ¿Cómo lo manejaron?
http no distingue tipos de error: todo cae en un mismo 
catch genérico
Sin interceptores: cada solicitud repite manualmente 
logging, encabezados, timeouts

--- p8 ---
Interceptores
Código que se ejecuta automáticamente antes o después de cada solicitud
Casos típicos: logging de cada petición/respuesta, inyección de encabezados de autenticación
Se registran una sola vez en la instancia de Dio y aplican a las tres operaciones por igual

--- p9 ---
Migrando GET, POST y PUT a Dio
dio.get(url) en lugar de http.get(Uri.parse(url)) — response.data ya viene decodificado
dio.post(url, data: datos) — data recibe un Map de Dart directamente, sin jsonEncode manual
dio.put('$url/$id', data: datosActualizados) — mismo principio que el POST

--- p10 ---
DioException: errores con nombre y apellido
connectionTimeout → no hubo respuesta a tiempo al 
conectar
receiveTimeout → conectó, pero la respuesta no llegó a 
tiempo
connectionError → no hay red o el servidor no es 
alcanzable
badResponse → el servidor respondió, pero con un 
código de error (4xx, 5xx)

--- p11 ---
http frente a Dio: comparación crítica
Boilerplate: http exige jsonEncode/jsonDecode manual 
en cada POST/PUT/GET; Dio lo hace por dentro
Manejo de errores: http devuelve un error genérico; Dio 
distingue tipos con DioException
Interceptores: http no los tiene de forma nativa; Dio sí, y 
aplican a GET, POST y PUT por igual
¿Cuándo basta http? Proyectos pequeños, pocas 
solicitudes, sin necesidad de interceptores
