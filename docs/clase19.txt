--- p6 ---
IDENTIDAD DEL FORMULARIO
La GlobalKey va en el State, nunca dentro de build()
Conecta el widget con su estado; currentState permite acceder al FormState desde cualquier parte del árbol.
class _PizzaPageState extends State<PizzaPage> {
final _formKey = GlobalKey<FormState>();
@override
Widget build(BuildContext context) {
return Form(
key: _formKey,
child: /* campos del formulario */ Column(),
);
}
}
Dentro de build() se crea una llave nueva en cada reconstrucción y se pierde la referencia al FormState real.

--- p7 ---
REGLA POR CAMPO
validator devuelve un mensaje de error o null
TextFormField = TextField + validación integrada. El callback recibe el texto y devuelve String?.
TextFormField(
validator: (value) {
if ((value ?? '').trim().length < 3) {
return 'Escribe al menos 3 caracteres';
}
return null;
},
)
null
El campo es válido.
Un mensaje
Hay un error y se muestra al usuario.

--- p8 ---
ANTES DE GUARDAR
validate() decide si algo se guarda
if (_formKey.currentState!.validate()) {
 _formKey.currentState!.save();
}
01
Recorre
validate() visita cada TextFormField.
02
Comprueba
Ejecuta el validator de cada campo.
03
Decide
Devuelve un resultado para todo el 
formulario.
Todos null → true
Se puede guardar.
Al menos un mensaje → false
No se envía nada.

--- p9 ---
EXPERIENCIA DE USUARIO
autovalidateMode define cuándo aparece el error
disabled
Solo al llamar validate().
El usuario termina y luego recibe 
los errores.
always
Valida desde el inicio y con 
cada cambio.
Desde el primer carácter, puede 
abrumar.
onUserInteraction
Valida tras interactuar con el 
campo.
Acompaña la corrección mientras se 
escribe.
La experiencia de usuario también es una decisión técnica.
